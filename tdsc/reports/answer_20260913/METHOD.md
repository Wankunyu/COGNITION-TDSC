# 2026-09-13 静态完整答案重跑

用户澄清的研究对象为“模型输出完整答案的能力”。每题只提供一次原始静态输入，只生成一次回答；不执行动作、不提供新观察、不根据正确性重试。CaptchaMind 原论文的交互式 agent 设计见 https://arxiv.org/html/2605.19538v1#S3.SS1 。此前交互开发集的 6/8 不属于本条件。

## 固定范围与调整

- A 原六类 141 题，B 原四类 200 题；Gemini 3.8 Flash 与 CaptchaMind-7B 均重跑。开发集仍为排除于 B 的既有 8 题，不扩充或重抽。
- 原图片、顺序、参考图、标签、逐题容差和评分器保留。A Click_Order/image8.png 的越界标签问题在正式生成前识别：保留全141题结果及原评分诊断，同时另列无该源问题的140题结果。
- 去掉 JSON-only/schema 约束，允许推理后输出完整答案；提示以 <answer> 包裹结论，但等价数值、坐标、列表、完整函数参数都可读取。函数文本仅作为答案表示，绝不执行。
- A Rotation 明确原素材和标签一致的顺时针方向、参考图/当前物体图顺序；删除评分器并未支持的泛化180°对称示例。没有根据模型正确率选方向或修改标签。
- 输出上限统一由8192提升至16384 tokens；请求超时600秒。模型温度0；Gemini thinking level仍MEDIUM。相同token上限不等同于相同计算量。
- 不设置 CaptchaMind 的额外格式 system 提示。MLX使用原BF16固定checkpoint和未修改的单轮服务；正确的image MIME、原始图片字节和显式输入尺寸保留。

## 答案读取与分母

提取器只读任务类型和输出文本，不读图片或GT，不改答案数值和顺序，不用正确性选修复。明确的非题设单位、残缺或冲突答案进入盲审。盲审可读任务说明和输出，不能看图片/GT；不能补全求解或重新询问模型。每项盲审决定与原文依据单独保存。

没有完整答案、含歧义或在预算内未答完，均留在固定题目分母中计失败。若达到输出上限但已给出可无歧义读取的完整答案，则按该答案评分，并保留截断标记。请求失败不能作为模型失败或悄悄移出分母；需明确报告未完成情况。全题成功率与排除预先识别源标注问题后的成功率均呈现。

openai.py:2276–2279 会将缺失的 finish reason 兜底为 stop，因此最终标签不构成逐 token EOS 证明。对这些回答只记“返回stop但无完整答案”，不推断其内部停止机制，也不把它们误写成16384 token耗尽。
