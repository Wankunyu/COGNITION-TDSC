# Solver and defense extension: execution protocol

Protocol date: 2026-09-13. The study was designed after inspection of the earlier static results and calibration records. The new conditions and defense comparisons are fixed before their formal generation; this is not a claim that the entire study was preregistered before any results existed.

The frozen A/B static complete-answer results in `../answer_20260913/` supply G-V and C-S. Newly generated conditions are CaptchaMind interactive episodes on the same 141 A and 200 B puzzles, plus three solvers on four paired defense conditions for 24 formal images. Development includes 12 separately drawn A puzzles, the eight previously excluded B calibration puzzles, and six D images in four conditions. Development observations never enter formal estimates. The complete executable specification is `../../configs/solver_defense_v1.json`; manifests, code copies, and full responses are preserved with every run.

G-V uses `gemini-3.8-flash`, temperature 0 and MEDIUM thinking. C-S and C-I use the same original BF16 `ATH-MaaS/CaptchaMind-7B` checkpoint at revision `b46c7a18f7647b0f4dbc4a2a10821e48239ca93a`. The specialist runs on task-local MLX-VLM 0.7.0 on the designated Mac Studio. This backend is a deployment difference from the published system, so results are not presented as an exact numerical reproduction. The Gemini model availability and current price were checked against the API and [official pricing](https://ai.google.dev/gemini-api/docs/pricing): input $0.75 and output including thinking $3.75 per million tokens.

G-V and C-S generate one complete answer from the original static image. They may reason before answering; the task-specific final answer is read using a deterministic extractor that cannot inspect the image or labels. D extensions map grid selections, unordered eye coordinates, and visible-eye counts onto the existing output forms. Any separate answer-reading adjudication uses only the public task and generated text, preserves values and units, and creates an external overlay rather than altering raw records. No model is asked again to repair an answer. A complete answer remains scoreable if the provider reports output truncation.

Six C-S development eye outputs used flat numeric lists or nested groups of coordinate pairs. A fresh, separate reading context received only the public prompt and response text. It resolved all six by pairing successive flat x/y values or flattening groups of explicit two-number points. The same generic rule was then added to the D-only explicit-final reader before formal generation and checked against every blinded reading. All values, points, order, and duplicates are retained. Malformed/mixed structures and explicit boxes requiring computed centers are rejected. Raw development outputs remain unchanged, and the frozen A/B extractor is not modified. No model call was added for this normalization.

C-I uses the enabled action prompt and observation/action loop from `AlibabaResearch/captcha-mind` revision `04e46b7673c361594e3f725720e49ab3bf7fb126`. The commented bounding-first prompt is not enabled. Each generation provides one action; the environment executes it and supplies a new observation. The B environments, images, candidate order, rewards, and stopping behavior are source-native. A and D are explicitly adapted environments: source image dimensions and origins remain unchanged, references remain separate and in their original order, and controls are appended below the puzzle. A angle entry preserves finite real values rather than adding rotation candidates. Eye selection supports hollow markers and Undo. The final submission, rather than an intermediate state selected using labels, determines success.

The initial adapted numeric panel displayed values as ordinary text. Development inspection identified an interface mismatch with the source action description, which permits `enter_number` when an input box is visible. Before formal generation, version `cognition_adapted_v1.1_numeric_input_box` adds a visible white bordered field for A Dice/Rotation and D2, displaying the original `str(number)` value. Puzzle pixels, reference order, Submit geometry, action values, and scores are unchanged. The entire initial 92-episode development round remains available. A separate fixed recheck includes all four A numeric and all six D2 development items, with at most 300 additional calls; no best-of merging is performed. The updated development ceiling is 1,668 calls, and formal plus development is 14,970 calls; formal counts and Gemini's 120 calls are unchanged.

The lossless action reader accepts complete JSON/XML wrappers without changing numbers or completing missing arguments. Source-supported actions are passed to B environments; the runner does not replace their type-dependent stopping rules with a blanket action whitelist. A source environment exception remains an unresolved engineering failure and stops dispatch for reconciliation. Invalid adapted-interface parameters, failure to produce a complete action, and budget exhaustion remain failed episodes. Complete actions in truncated generations can still execute. Distinct status fields preserve these mechanisms.

One C-I episode permits at most 30 model calls, 8,192 output tokens per call, 65,536 completion tokens in total, 600 seconds per request, and 1,800 seconds per episode. These are study budgets, not a claim that every original batch experiment used these values. Static output is capped at 16,384 tokens. The deployed checkpoint has a 128,000-token native context limit, smaller than the tokenizer's 131,072 declaration; the service explicitly enforces 128,000 without pruning history. Usage includes the provider's completion accounting. Independent reasoning fields are saved but not inserted back into assistant message content. The API's original content and each observation are retained in their originating turn.

During formal A, an in-flight request reached the existing 1,800-second episode deadline and the original runner conservatively stopped the study with a pending request. Following authorization to debug and continue, execution policy `episode_deadline_reconciliation_v1` makes this boundary consistent with deadline exhaustion between calls. A separate derived record marks failure to complete within the episode budget only when the original dispatch, timeout, and elapsed-time evidence establish that the episode deadline caused the timeout and no submission occurred. The unavailable response and original pending record remain unchanged; no request is resent and no late action is executed. The dedicated inference service must finish its outstanding request before the next independent episode starts. Other transport failures remain unresolved and halt dispatch. For a missing final response, complete episode token usage remains unknown, with observed-prefix counts stored separately. The frozen experiment code, manifests, model inputs, scoring functions, and all budgets remain unchanged; policy code and original runtime records are archived in `execution_fixes/episode_deadline_reconciliation_v1/`.

A task-local MLX correction preserves the originating image markers in multimodal history. Eight single-round prompt configurations were byte-identical before and after the correction; two- and three-round marker positions changed from `[0,2]` and `[0,0,3]` to `[1,1]` and `[1,1,1]`. Image order and assistant content were unchanged. Runtime versions, actual processor configuration, source evidence, the patch, and restoration instructions are in `runtime/`. The exact deployed context-limit error text was added to the runner's budget classification after A development started, without changing any model-visible content, action, score, or budget; this zero-call change is recorded in `engineering_changes.json`.

Development inspection also checked whether recurrent submission-coordinate offsets came from preprocessing. The actual processor maps a 400×420 image to a 392×420 pixel grid (`image_grid_thw=[[1,30,28]]`, patch14); the observed downward offset is not explained by that transform. MLX explicitly shares its Qwen3VL-named image processor with Qwen2.5-VL while reading this checkpoint's patch, merge, and pixel parameters. The direct blank-image measurement and implementation evidence are preserved in `runtime/preprocessor_check.json`; no coordinate rescaling or button relocation was introduced in response to model outputs.

Requests are saved before dispatch and raw responses immediately after receipt. A resumed episode may replay saved actions locally to reconstruct deterministic state, then continue within the same episode. A dispatched request with no saved response is unresolved and cannot be automatically resent. Completed episodes are never regenerated. Prompt changes, manifest changes, and implementation changes cannot silently enter an existing frozen run. The native source loaders use shared module state, so specialist episodes run sequentially.

All 30 D source images and targets were visually audited before new generation. Twenty-four formal base images remain, with no exclusions or replacement from development. Independent journal labels correct three development-only records (images 8, 23, and 27). D0 asks for original target grid cells; D1 asks for all actually visible eyes of that same target; D2 asks only for the number of visible eyes; D3 applies Pillow GaussianBlur radius 2.0 pixels to the puzzle image for D0. Instructions and controls are not blurred. The original target includes two personified objects, robot and star, which are retained and identified in the audit. Prior public or historical use prevents claiming unseen training exposure.

D1 succeeds only when prediction and label cardinalities agree and a complete one-to-one maximum bipartite matching exists within 15 pixels, including the distance boundary. The same saved submitted answer is also scored at 30 and 45 pixels. A compatibility view uses the old nearest-greedy algorithm on the same audited labels; it can exhibit order-dependent false negatives, but its full-coverage success is already monotone with increasing radius. No historical conference score is overwritten. A and B keep their original scoring rules. A reports the source-valid 140-item view and the complete 141-item diagnostic view separately.

Formal analysis preserves all fixed denominators. Missing responses, unresolved environment or provider failures, and pending answer readings are explicit unknowns, not silently deleted items or presumed model errors. A/B estimates include per-type, macro, and micro results with paired material-group bootstrap within type. D resamples whole base images with every condition and radius bound together: 10,000 bootstrap draws, seed 20260913. The primary defense quantity is the within-solver D0 minus D1 success-rate difference. The C-S minus C-I difference of those drops describes the protocol bundle, not a training or feedback causal effect. Paired transition cells, baseline floor effects, D2/D1 disagreements, localization tolerance, missing and extra points, and request/token/time costs accompany success rates.

After formal generation and independent format-only adjudication, the author explicitly directed that answers remaining ambiguous count as failures. Policy `ambiguity_as_failure_v1` therefore classifies all seven reviewed ambiguous C-S D1 responses as `ambiguous_answer_failure`. Their raw responses and blind-reading decisions remain unchanged; standard answers stay null, and no coordinates are inferred. These seven outcomes are failures in success rates, paired effects, and all tolerance views, while unreadable coordinates remain excluded from coordinate diagnostics with the diagnostic denominator reported separately. This is a post-generation author-directed scoring policy change, not a preregistered rule. Missing responses, unfinished requests, and unresolved infrastructure failures retain their original treatment. The prior unknown-outcome analysis is archived in `execution_fixes/ambiguity_as_failure_v1/before/`.

Results concern offline machine solving under these protocols. The experiment provides no new human usability evidence and does not compare external defense methods. The complete reproduction entry points are `../../scripts/run_solver_defense_v1.py` for fixed phases and `../../scripts/summarize_solver_defense.py` for offline analysis. Progress and completion are stated in separate reports so an unfinished run cannot be mistaken for a final result.

During interim analysis of the running formal B condition, the frozen Dice_Count manifest was confirmed to contain only one shared-material group across its 50 records. A group bootstrap cannot estimate between-group uncertainty from that single group. The reporting layer therefore retains point estimates and paired cells but suppresses intervals for types with fewer than two groups and for micro/macro aggregates containing such types, naming the affected types. Other types retain the fixed bootstrap unchanged. Degenerate intervals with multiple groups are flagged and do not establish zero population uncertainty or equivalence. This reporting correction was added after formal generation started; manifests, scores, model requests, and the resampling method are unchanged. Its provenance is recorded in `analysis_changes.json`.
